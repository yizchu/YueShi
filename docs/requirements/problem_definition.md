# 教学能力评估智能体

> 面向大学生家教的**教学能力评估方法**研究
> 第一版限定范围：**初中学段 × 数学学科**

---

## 一、5W1H 报告

### 1.1 What —— 做什么

**产品**：面向大学生家教的「初中数学教学能力基础准入与诊断模型」，即一个**教学能力评估智能体**。

**备注**：由于不同学段和学科的教学能力评估标准和难易程度不同，所以本项目限定了一个特定的范围。

**评估手段**：

- 情景模拟试讲（重点研究）：提供讲题场景和虚拟学生，评估者试讲并和虚拟学生互动。智能体给整个过程打分并提供改进建议。
- 多次评估：评估者可根据改进建议再次参与评估，每次评估结果会迭代更新。

**产出四样东西**：

1. 准入判定（通过 / 待定 / 未过）
2. 教学能力总分（0~100）与 5 个分维度得分
3. 能力画像（雷达图 + 标签 + 改进建议）
4. 讲稿与问答存档（供下游复核回溯）

### 1.2 Why —— 为什么做

**核心矛盾**：家长挑选大学生家教时，现有信息只能证明他"**会做题**"，不能证明他"**会讲课**"。

| 现有依据 | 问题 |
|---|---|
| 看学校、专业、高考分数 | 只反映做题能力，与讲解能力不相关 |
| 靠中介推荐 | 主观、无标准、不可比 |
| 靠试课试错 | 家长要付出真实时间与金钱成本 |
| 靠同学转介绍 | 覆盖面窄，无法规模化 |

**三方痛点**：

- **家长**：缺可靠判断依据，试错成本高
- **大学生**：缺客观可展示的能力凭证，在家长不愿试错的情况下，只能靠"我是某某大学的"自我证明
- **平台**：难以对教师的教学能力进行准确量化并应用到推荐排序中

### 1.3 Who —— 谁参与

| 角色 | 诉求 | 在系统中的位置 |
|---|---|---|
| **大学生（被评估者）** | 快速拿到可信认证；改进自己的短板 | 主要使用者 |
| **家长 / 学生** | 找到"讲得清楚"的老师 | 结果消费者 |
| **平台运营** | 控制准入质量、处理申诉与纠纷 | 规则制定与仲裁 |
| **推荐系统** | 获取可靠的教学能力信号 | 下游消费者 |

> **注意**：真正的终端学生**不直接参与**教学能力评估——评估一律使用虚拟场景模拟学生，不需要真实学生出镜。

### 1.4 Where —— 在哪里发生

- **物理场景**：由下游推荐系统及家教平台决定，**本项目不负责平台的搭建**。
- **业务位置**：```
注册 → 实名/学籍认证 → 【情景模拟试讲评估】
     → 试讲认证标识 → 进入推荐池```

### 1.5 When —— 何时发生

| 时点 | 事件 |
|---|---|
| **首次触发** | 大学生完成实名认证、申请成为家教时 |
| **评估周期** | 异步多轮，总时长约 25~45 分钟（试讲 1 轮 + 答辩多轮） |
| **认证有效期** | 不设限 |
| **重试** | 未通过者可多次尝试 |
| **申诉** | 可随时提出对智能体的使用反馈 |

### 1.6 How —— 怎么做

**评估方法**（第一版简化方案）：

1. **异步多轮**：老师写出教案，再由系统给出文本疑问，老师写文本回应
2. **疑问后置揭示**：备课只给题目，讲完才揭示疑问，保住"临场应变"的考察价值
3. **多源评分**：LLM 按 rubric 分维度打分（逐条给理由）+ 规则维度（口头禅 / 字数）

**评估方法**（最终方案）：
1. **异步多轮**：老师提交讲稿，再由系统给出文本疑问，老师提交文本回应


**技术实现**：LLM 文本评分（讲稿输入），不自研模型（详见 [open-source-stack.md](../open-source-stack.md)，开发过程中可根据实际情况调整）。人工复核属下游产业环节，不在本系统范围。
