## 0. 范围说明

本规范覆盖**讲题教学能力评估工具**（输入为**逐字讲稿 + 3 轮文本问答**），部署形态为**单机本地运行**（CLI 或 FastAPI + 静态页）。以下内容**不在范围内**：

- 学科知识准入测试（默认被试已掌握学科知识）
- 人工复核 / 申诉（属下游环节）
- 听觉评估（连贯性、口齿清晰）、视觉评估（读稿、板书）
- 音视频采集 / 视频转录
- 家教平台的订单、支付、IM、推荐算法
- 其他学段与学科
- 账号体系、多租户、后台运营系统

> 非功能需求必须**可度量、可验证**。每条给出目标值与验证方式；状态标注见 §0.1。
> 输出必须**可复核**（逐项理由与证据），供下游开展人工复核——体现在 NFR-Q2。

## 2. 性能需求 (NFR-P)

| 编号 | 需求 | 目标值 | 验证方式 | 状态 |
|---|---|---|---|---|
| NFR-P1 | 问题生成时长 | 3 问 + 参考要点在一次 LLM 调用内完成，**≤ 60 秒**（P95，真实模型） | 实测计时 | 🟡 依赖模型 |
| NFR-P2 | 单轮问答响应 | 提交回答 → 落盘 → 揭示下一问 **≤ 1 秒**（问题已预生成，无网络调用） | 实测 | ✅ |
| NFR-P3 | 评分时长 | 4~5 次 LLM 调用（通用/采分点/问答/建议），**≤ 3 分钟**（P95） | 实测计时 | 🟡 依赖模型 |
| NFR-P4 | 端到端出报告 | 第 3 轮回答提交至报告可见 **≤ 5 分钟**（P95） | 全链路计时 | 🟡 依赖模型 |
| NFR-P5 | 报告页加载 | 本地首屏 **≤ 1 秒**（静态文件 + 单次 API） | 手工计时 | ✅ |
| NFR-P6 | 并发能力 | **≥ 5** 个会话并行（单进程 uvicorn + 内存态，实际瓶颈是 LLM 速率） | 并发脚本 | 🟡 未压测 |
| NFR-P7 | 冷启动 | `python web.py` 启动可用 **≤ 3 秒** | 实测 | ✅ |

> **说明**：v2.0 的「≥ 50 并发」按服务化假设编写；本版为单机工具，不设队列与多 worker，并发目标下调。实测：dry-run 全链路（抽题→3 轮→评分→报告，含解释器启动）约 **5 秒**；`import web` 约 1.5 秒。

## 6. 评分质量需求 (NFR-Q) —— 核心

> 评分质量不达标，整个系统不成立。

| 编号 | 需求 | 目标值 | 验证方式 | 状态 |
|---|---|---|---|---|
| **NFR-Q1** | **与专家评分一致性** | Kappa / ICC **≥ 0.75** | 双评分者一致性统计（需专家样本） | ⬜ 未开展 |
| NFR-Q2 | 可解释、可复核 | **每个评分项必附理由与原文证据**；采分点逐条给判定与依据 | 结构校验 | 🟡 提示词强制；缺证据时报告留空，无自动拦截 |
| NFR-Q3 | 可复现性 | 同输入 + 同标准 + 同模型 + 温度 0.5，档位偏差 **≤ 1 档** | 重复评分实验 | 🟡 未系统验证 |
| NFR-Q4 | 版本可追溯 | `meta` 记 model / 时间 / 调用次数；提示词版本未入库 | 数据核查 | 🟡 |
| **NFR-Q5** | **采分点判定稳定性** | 核心采分点「覆盖/未覆盖」多次判定一致率 **≥ 90%** | 重复判定实验 | ⬜ 未开展 |
| NFR-Q6 | 理由无幻觉 | 理由不得引入原文不存在的内容，不合规率 **< 2%** | 抽样核查 | ⬜ 未测 |
| NFR-Q7 | 多轮自一致性 | 同输入独立评 3 次取中位数，档位一致率 **≥ 90%** | 重复评分 + 方差 | ⬜ N=3 未实现 |
| NFR-Q8 | 区分度 | 各评分项分布标准差 **> 0.8**，避免全给中间分 | 分布统计 | ⬜ 未测 |
| NFR-Q9 | 内部一致性 | 同层各维度 Cronbach's α **≥ 0.7** | 统计分析 | ⬜ 未测 |
| NFR-Q10 | 重测稳定性 | 同一人两次评估评级一致或仅差 1 档 | 重测实验 | ⬜ 未测 |
| **NFR-Q11** | **门槛规则可靠性** | 核心采分点未覆盖时评级限制 **100% 生效**，不被其他高分掩盖 | 单元测试 | ✅ 程序侧强制，有测试 |
| NFR-Q12 | 建议相关性 | 建议必须指向实际失分项，抽检相关率 **≥ 90%** | 抽样核查 | 🟡 提示词约束 |
| **NFR-Q13** | **报告排版正确性** | 正文不得出现未转义的 `^`（次方一律 Unicode 上标）；表格单元格内 `\|` 转义，列数不因内容错位 | 单元测试 | ✅ |

> **Q1 说明**：产品流程不含人工复核；研究阶段仍须用**专家评分**（少量样本）作为验证手段。
> `Q5/Q7` 依赖 N=3 采样与批量评测（均未实现），是当前最大的质量缺口。

## 10. 成本需求 (NFR-$)

| 编号 | 需求 | 目标值 | 状态 |
|---|---|---|---|
| NFR-$1 | 单次评估成本 | **≤ 1 元 / 次** | ✅ 当前 N=1 约 ¥0.2 |
| NFR-$2 | 算力门槛 | 只用 LLM API，**不强制 GPU** | ✅ |
| NFR-$3 | 存储成本 | 全文本（讲稿 + 报告），可忽略 | ✅ |
| NFR-$4 | 幂等不重复计费 | 重复评分不重复调用 | ✅ |

> **成本测算（N=1，按 deepseek-chat 量级）**：
> - 问题生成 1 次：≈ 5k tokens → ≈ ¥0.05
> - 评分 3 次（通用 / 采分点 / 问答）+ 建议 1 次：≈ 12k tokens → ≈ ¥0.15
> - **合计 ≈ ¥0.2 / 次**；若实现 N=3 采样，评分部分 ×3 → ≈ ¥0.5 / 次，仍在 1 元内。

### 验收门槛（v3.0）

> **本版验收以「可运行、可复核、排版正确」为准**：
> 1. **33 项自动化测试全部通过**（含门槛规则、逐轮揭示、幂等评分、排版归一、表格转义）；
> 2. **dry-run 全链路可跑通**（无 API key 也能出完整报告），真实模型下抽题→3 轮→评分→报告可完成；
> 3. **报告可复核**：每个评分项有理由与原文证据，核心采分点缺失必然触发评级封顶（NFR-Q11）。

> **研究验收（未达成）**：
> 1. **NFR-Q1**：评分与专家一致性 ≥ 0.75（需专家样本与批量评测）；
> 2. **NFR-G1 / G2**：问题「合理且互不重复」抽检 ≥ 95%（需人工抽检）。
>
> 这两条是系统对外宣称「能替代人工初评」的前提，当前尚不具备实验数据支撑。
