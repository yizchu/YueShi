> 项目：教学能力评估智能体（约师）
> 版本：v1.1 ｜ 文档类型：需求阶段 — 非功能需求规范
> 配套文档：[functional_spec.md](functional_spec.md) · [problem_definition.md](problem_definition.md)

---

## 0. 范围说明

本规范仅覆盖**教学能力评估智能体**（输入为**讲稿文本**）。以下内容**不在范围内**：

- 学科知识准入测试（不做、不设计、不依赖）
- **音视频采集与语音转写**（当前为讲稿文本输入）
- **人工复核 / 申诉**（属下游产业环节，由使用者接入后自行完成）
- 家教平台的订单、支付、IM、搜索推荐等业务功能
- 其他学段与学科
- 实时语音交互与视频多模态分析

> 非功能需求必须**可度量、可验证**。本文每条需求均给出目标值与验证方式。
> **注意**：本系统的输出必须**可复核**（含逐维度理由与证据），以便下游产业自行开展人工复核——这是"研究输出接入下游"的接口约定，体现在 NFR-Q2。

## 2. 性能需求 (NFR-P)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-P1 | AI 评分时长 | 单次全部维度评分 **≤ 3 分钟**（P95）；N 次采样**并行**，端到端延迟基本不变 | 批量压测统计 |
| NFR-P2 | 端到端出分 | 最后一轮回应提交至报告可见 **≤ 5 分钟**（P95） | 全链路埋点 |
| NFR-P3 | 报告页加载 | 首屏 **≤ 3 秒**（P95） | 前端性能监控 |
| NFR-P4 | 并发能力 | 支持 **≥ 50** 个会话并行处理不排队 | 压测 |

> **多轮假设**：答辩轮数由题目「疑问队列」长度决定，建议每道题预置 1~3 条疑问，并设轮次上限（≤ 5 轮）兜底。

## 3. 可靠性与可用性 (NFR-R)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-R1 | 异步任务可靠性 | 评分任务**至少执行一次**，失败自动重试 ≤ 3 次 | 任务日志核查 |
| NFR-R2 | 系统可用性 | 月度可用性 **≥ 99.5%** | 监控统计 |
| NFR-R3 | 数据持久性 | 讲稿、问答与评分数据年丢失率 **< 0.01%** | 存储冗余核查 |
| NFR-R4 | 幂等性 | 重复提交同一会话不产生重复评分或重复发证 | 接口测试 |

---

## 4. 安全与隐私 (NFR-S)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-S1 | 传输加密 | 全链路 **TLS 1.2+** | 安全扫描 |
| NFR-S2 | 存储加密 | 讲稿与个人信息静态加密 **AES-256** | 配置核查 |
| NFR-S3 | 访问控制 | 试讲者**仅可访问本人**材料 | 越权测试 |
| NFR-S4 | 数据删除权 | 用户注销后 **30 天内**删除讲稿与个人信息 | 流程审计 |
| NFR-S5 | 审计日志 | 全链路关键操作留痕，**留存 ≥ 6 个月** | 日志核查 |
| NFR-S6 | 敏感信息最小化 | 讲稿文本入库前脱敏（手机号、住址等） | 抽样核查 |

## 5. 合规需求 (NFR-C)

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-C1 | 生成式 AI 服务备案 | 若 AI 评分对外提供服务，需完成相关备案 |
| NFR-C2 | 个人信息保护 | 遵循告知同意、最小必要原则，提供查阅 / 更正 / 删除通道 |

| NFR-C4 | 数据出境 | 若使用境外模型 / 服务，须评估数据出境合规性 |

## 6. 评分质量需求 (NFR-Q) —— 核心

> 本节是本项目**最重要的非功能需求**。评分质量不达标，整个系统不成立。

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| **NFR-Q1** | **评分与专家评分一致性（研究验证）** | Kappa / ICC **≥ 0.75** | 双评分者一致性统计 |
| NFR-Q2 | 评分可解释、可复核 | **每个维度得分必须附带文字理由与证据引用**，供下游人工复核 | 结果结构校验 |
| NFR-Q3 | 评分可复现性 | 同一输入 + 同一 rubric 版本 + 同一模型版本，档位偏差 **≤ 1 档** | 重复评分实验 |
| NFR-Q4 | 版本可追溯 | 每条评分记录可追溯至具体 **rubric 版本 + 提示词版本 + 模型版本** | 数据核查 |
| NFR-Q5 | 讲错扣分一致性 | 科学性错误应稳定归入「讲解逻辑/表达清晰度」并降档，不因模型不同而漏判 | 抽样核查 |
| NFR-Q6 | 理由无幻觉 | 评分理由**不得引入讲稿/问答文本中不存在的内容**，不合规率 **< 2%** | 抽样核查 |
| NFR-Q7 | 多轮自一致性 | 同模型同输入评 N 次，维度档位**一致率 ≥ 90%**（或用变异系数检测不稳定维度） | 重复评分 + 方差分析 |
| NFR-Q8 | 区分度 | 各维度评分分布标准差 **> 0.8**，避免全给中间分 | 分布统计 |
| NFR-Q9 | 内部一致性 | 维度间 Cronbach's α **≥ 0.7** | 统计分析 |
| NFR-Q10 | 重测稳定性 | 同一人两次试讲总分差异 **≤ 10 分** | 重测实验 |

> **Q1 说明**：本系统的产品流程**不含人工复核**；但研究阶段仍须用**专家评分**（少量样本，作为研究验证手段）证明智能体可靠。这与"产品是否做人工复核"是两回事。

## 7. 可维护性与可扩展性 (NFR-M)

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-M1 | Rubric 可配置 | 调整维度 / 分档描述 / 权重 / 阈值**无需改代码** | 配置化验证 |
| NFR-M2 | 供应商可替换 | LLM 通过适配层接入，**可替换供应商而不影响业务代码** | 接口抽象审查 |
| NFR-M3 | 提示词版本化 | 评分提示词纳入版本管理，支持灰度与回滚 | 版本系统核查 |
| NFR-M4 | 线性扩展 | 增加评估量时可通过扩容 worker 线性提升吞吐 | 压测 |
| NFR-M5 | 学科扩展预留 | 数据结构预留多学科字段（**本期不实现新学科**） | 模型评审 |

## 9. 成本需求 (NFR-$)

| 编号 | 需求 | 目标值 |
|---|---|---|
| NFR-$1 | 单次评估 AI 成本 | LLM 调用合计 **≤ 1 元 / 次**（含 N 次采样，N=3 时 ≈ ¥0.3） |
| NFR-$2 | 算力门槛 | 第一版**走 LLM API 即可**，不强制要求 GPU |
| NFR-$3 | 存储成本 | 讲稿与问答为文本，存储成本可忽略 |

> **成本测算**（平均 2 条疑问 = 讲稿 + 2 段回应文本）：讲稿约 1000~2000 字、回应约 500~1000 字，合计约 3000 字（≈2500 tokens），LLM 输入约 4500 tokens（含 rubric 提示）、输出约 750 tokens。按中档 API 计，**单次 ≈ ¥0.1**；多轮采样 N=3 → **≈ ¥0.3 / 次**，仍远低于 1 元预算。

| 编号 | 需求 | 目标值 |
|---|---|---|

## 12. 需求优先级与验收

| 优先级 | 编号 | 说明 |
|---|---|---|
| **P0 必须达标** | NFR-Q1 ~ Q5、NFR-R1、NFR-S1 ~ S3、NFR-C2 ~ C3、NFR-P1 ~ P2 | 不达标则系统不成立 |
| **P1 重要** | NFR-P3 ~ P4、NFR-R2 ~ R4、NFR-S4 ~ S6、NFR-Q6 ~ Q10、NFR-M1 ~ M3、NFR-O1 ~ O4、NFR-$1 ~ $2、NFR-X1 ~ X3、NFR-U1 ~ U4 | 第一版应有 |
| **P2 可延后** | NFR-C1、NFR-C4、NFR-M4 ~ M5、NFR-$3 | 视上线节奏安排 |

### 验收门槛（一句话）

> **NFR-Q1（评分与专家评分一致性 Kappa / ICC ≥ 0.75）是整个系统的验收红线**，其余需求围绕它服务。
