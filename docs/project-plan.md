## 一、一句话定位

**给大学生家教做「初中数学教学能力」的评估智能体**：给定一道初中数学题，教师提交讲稿 + 多轮文本答疑，AI 按 rubric 从 4 维度打分，输出「通过 / 待定 / 未过 + 能力画像 + 改进建议」，作为家教平台推荐的核心权重。

**只评"会不会讲"，不评"会不会做"**（学科知识默认教师已掌握，不单设维度；讲错归入讲解逻辑/表达清晰度扣分）。

## 二、评估模型（宏观结构）

### 2.1 两个环节（类比教资面试）

| 环节 | 轮次 | 内容 | 形式 |
|---|---|---|---|
| **试讲环节** | 第 1 轮（固定） | 讲题（概念/例题/易错点） | 讲稿（文本） |
| **答辩环节** | 第 2~N 轮（循环） | 文本疑问 → 教师回应 | 回应文本 |

### 2.2 五种题型

| 环节 | 题型 | 对应 MKT 子域 |
|---|---|---|
| 试讲 | ① 概念阐释题 | SCK |
| 试讲 | ② 例题讲解题 | KCT |
| 试讲 | ④ 分层适配题 | KCS + KCT |
| 答辩 | ③ 错因诊断题 | KCS + SCK |
| 答辩 | ⑤ 答疑应变题 | 回应与应变 |

### 2.3 四个评分维度

| 维度 | 权重 | 说明 |
|---|---|---|
| 讲解逻辑 | 30% | 导入→讲解→例题→小结的条理；**讲错（推理/步骤错）在此降档** |
| 表达清晰度 | 20% | 用词、术语、口头禅、啰嗦程度；**术语/表述错在此降档** |
| 学情适配 | 25% | 是否匹配学生水平、是否降维 |
| 错因诊断 | 25% | 预防面（主动强调易错点）+ 纠正面（出错后诊断） |

### 2.4 判定规则

```
总分 = Σ(维度档位分 × 权重) ÷ 5 × 100
```

| 判定 | 条件 |
|---|---|
| 通过 | 总分 ≥ 70，且无任一维度 ≤ 2 |
| 待定 | 总分 60~69，或存在单一维度 ≤ 2 |
| 未过 | 总分 < 60 |

## 三、端到端流程

```
抽题（只给题干 + 学生人设，不给疑问）
   ↓
【试讲】提交讲稿
   ↓
【答辩】逐轮：揭示疑问 → 提交回应文本 → 队列耗尽
   ↓
全部文本 → LLM 按 rubric 4 维度打分 + 规则指标（口头禅/字数）
   ↓
报告 + 认证标识
```

## 四、关键设计决策（附依据）

| 决策 | 依据 |
|---|---|
| 只做初中数学 | MKT 是分专题的（[hill-2008](research/hill-2008-unpacking-pck.md)） |
| 不设知识测试（默认教师已掌握学科知识） | [基本假设.txt](基本假设.txt)；会做题 ≠ 会讲课（[ball-2008](research/ball-2008-content-knowledge-for-teaching.md)） |
| 4 维度映射 MKT 子域 | [ball-2008](research/ball-2008-content-knowledge-for-teaching.md) |
| 错因诊断分预防/纠错两面 | [ball-2008](research/ball-2008-content-knowledge-for-teaching.md) + 你的 [Todo](Todo.md) |
| **1~5 档** | 0-5 档人机一致性最高（[li-2026](research/li-2026-grading-scale-llm-judge.md)） |
| 异步多轮 + 文本疑问 | 工程简化（见 [functional_spec](requirements/functional_spec.md) §2/§4） |
| **评分 prompt 必须带示例** | 只给 rubric 失效、带示例才显著（[qi-2025](research/qi-2025-llm-teaching-content-quality.md)） |
| 用 ICC/Kappa 而非 accuracy | 三篇同证（li-2026、qi-2025、[thakur-2025](research/thakur-2025-judging-the-judges.md)） |
| 输出可复核（证据+理由） | 人工复核属下游产业，输出须支持复核（[shakur-2026](research/shakur-2026-oasis.md)） |

## 五、已知风险与待决问题（open issues）

### 5.1 路线级风险：GPT 式 prompting 够不够？

[Measuring Teaching with LLMs](research/survey-llm-assessment-systems.md) 发现**通用 GPT 式 LLM 对复杂教学量表"表现有限"**，需要专用微调模型。

- **约师的可能不同**：约师场景更窄（一对一讲题、短、结构化），可能够用。
- **但必须验证**：这是第一优先级要回答的问题。

### 5.2 0.75 信度目标是否乐观？

三份证据都显示教学评估信度天然低：

- MathDial 教学动作标注 κ=0.60
- li-2026 主观题 LLM 信度 0.57~0.63
- qi-2025 甚至没报告信度

→ 0.75 是"目标"而非"基线"，达不到要有降级方案（结果分级 + 阈值校准 + 或退化为排序）。

### 5.3 未决：题型 = 题目类型，还是评分锚点？

- **方案 A**：题型是独立题目类型（抽一道"错因诊断题"单独讲）
- **方案 B**：题型是"评分锚点"（抽一个知识点，用户连贯讲，系统按锚点找证据）

你倾向哪个？这会影响题目设计与评分 prompt 结构。

### 5.4 未决：评分示例从哪来？

qi-2025 证明示例关键，但约师还**没有准备"高质量 / 普通"讲稿样例**。这是评分 prompt 能生效的前提。

## 六、与你 Todo 的对应

你记的：

> 「试讲是否可以预防学生出错，是否提前强调了所有的重点」

这正是 **「错因诊断·预防面」** 的评估内容。落地方式：

1. 每道题的「评分要点」里，写清该题的**核心易错点清单**；
2. 评分时检查老师**是否主动覆盖**这些易错点（而非等学生出错）；
3. 对应的 Rubric 档位已在 A4（学情适配）与 A5（错因诊断）中体现。

## 七、下一步（建议执行顺序）

1. **定 5.3 的方案 A/B**（题型定位）
2. **准备 2~3 份评分示例**（高质量 + 普通讲稿，喂给评分 prompt）
3. **格式验证**：用教资试讲逐字稿冷启动，跑通评分 prompt 的输出格式
4. **一致性验证**：收集 3~5 份真实试讲，测 AI 与专家评分一致性（NFR-Q1）
5. **根据结果决策**：若信度不达标 → 升级（示例工程 / 微调专用评估器 / 或降级为排序）
