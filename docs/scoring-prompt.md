# 评分 Prompt 草案（多轮结构化）

> 目的：把 Rubric 转成 LLM 可执行的评分指令，支持**异步多轮**（试讲 1 轮 + 答辩多轮）的讲稿 / 问答文本输入。
> 配套：[functional_spec.md](requirements/functional_spec.md)（状态机 / 领域模型）· [nonfunctional_spec.md](requirements/nonfunctional_spec.md)（NFR-Q 质量指标）
> 状态：草案 v0.1，待用真实试讲样本做一致性验证后迭代。

---

## 1. 目的与定位

评分 prompt 是整条流水线的"标准答案"——它决定 AI 评分是否可信（NFR-Q1 一致性 ≥ 0.75 的源头）。设计要点：

1. **多轮结构化输入**：讲稿与问答文本按轮次分段喂入，而不是把所有内容糊成一整段。
2. **rubric 全量嵌入**：4 维度 × 5 档行为描述直接写进 system prompt，作为唯一评分依据。
3. **强制证据链**：每个维度的理由必须引用原文，杜绝 LLM 幻觉（NFR-Q6）。
4. **输出可解析**：固定 JSON schema，便于程序化合成总分与判定。

---

## 2. 输入格式（多轮结构化）

每次评分，user prompt 组装如下（`{{ }}` 为占位符）：

```
【题目信息】
- 题号：{{题号}}
- 题型：{{题型}}（{{环节}}）
- 知识点：{{年级}} · {{知识点}}
- 难度：{{难度}}
- 学生人设：{{学生人设}}
- 教学目标：{{教学目标}}
- 评分要点：{{评分要点}}
- 常见偏差：{{常见偏差}}
- 评分参考：{{评分参考}}（含内容采分点 + 教学行为观察点，见 datasets/）

【试讲环节 · 第 1 轮】（讲稿）
{{讲稿文本}}

【答辩环节 · 第 2 轮】
学生疑问：{{疑问1文本}}
老师回应：{{回应1文本}}

【答辩环节 · 第 3 轮】
学生疑问：{{疑问2文本}}
老师回应：{{回应2文本}}

（轮数由题目「疑问队列」长度决定，2~N 轮；无追问时此段省略）
```

> 评分要点 / 常见偏差来自题目本身（见 scenario-cards.md），它们与 rubric 一起构成评分锚点——这解决"AI 不知道这道题该讲什么"的问题。

## 3. 评分维度与 Rubric（嵌入版）

以下 4 张表原样嵌入 system prompt。

> **学科准确性不在本 rubric 范围**：默认教师自身具备应有的学科知识。若讲稿中出现科学性错误（讲错），不单设维度，而是根据错误性质在「讲解逻辑」（推理/步骤错）或「表达清晰度」（术语/表述错）上降档——这正是典型的"自己会但不会教别人"。

### 3.1 讲解逻辑（权重 30%）

| 档 | 行为描述 |
|---|---|
| 5 | 结构完整（导入→讲解→例题→小结），因果链清晰，能说明"为什么这一步要这么做"，前后呼应；无科学性错误 |
| 4 | 结构完整、条理清楚，个别环节衔接略生硬；无科学性错误 |
| 3 | 能把内容讲完，但基本是"照着步骤念"，缺少"为什么"，结构松散 |
| 2 | 顺序混乱、跳跃，学生难以跟上；或出现明显不严谨、可能误导学生的表述 |
| 1 | 逻辑自相矛盾，或出现明显的科学性错误（讲错），或无法组织出完整讲解 |

### 3.2 表达清晰度（权重 20%）

> 纯文本版：只评「书面/讲稿」的表达质量，**不涉及语速、停顿、声音等听觉因素**（视觉/听觉后续由其他模块测评）。

| 档 | 行为描述 |
|---|---|
| 5 | 语言简洁准确，用词规范且会把术语讲成人话（口语化转换自然），重点处有清晰强调，几乎无口头禅，读来通顺流畅 |
| 4 | 表达清楚、用词基本准确，偶有口头禅或个别啰嗦处，但不影响理解 |
| 3 | 能看懂，但术语堆砌、或过度口语化、或语句冗长，口头禅较多 |
| 2 | 表达含糊、重复啰嗦，需反复阅读才能理解；或术语用错、表述有科学性错误 |
| 1 | 语言混乱、用词错误（含术语系统性误用），或几乎无法理解 |

### 3.3 学情适配（权重 25%）

| 档 | 行为描述 |
|---|---|
| 5 | 准确判断并贴合学生水平，主动降维（换更简单的例子或类比），能用学生已有知识搭桥，预判学生难点 |
| 4 | 讲解难度基本匹配学生水平，有解释与铺垫意识 |
| 3 | 内容正确，但按自己的习惯难度讲，未考虑学生基础 |
| 2 | 明显超出或低于学生水平，使用了学生尚未学的工具 |
| 1 | 完全无视学生人设，自说自话 |

### 3.4 错因诊断（权重 25%）

| 档 | 行为描述 |
|---|---|
| 5 | 准确指出错误步骤与背后的概念误解，用学生能懂的方式重建正确认知，并给出防止再犯的方法 |
| 4 | 准确指出错误步骤并解释原因，但重建方式一般 |
| 3 | 能指出"这里错了"，但停留在运算层面，未触及概念原因 |
| 2 | 仅给出正确答案，未解释错因 |
| 1 | 未发现错误，或自身讲解出现科学性错误 |

> **两面说明**：本维度分「预防」「纠错」两面。上表 1~5 档描述**纠正面**（第 2~N 轮，学生出错后定位纠错）；**预防面**（第 1 轮讲题时主动预判并强调易错点）由学情适配维度与题目评分要点共同覆盖。

## 4. 评分规则与约束

1. **就低不就高**：行为介于两档之间时取较低档。
2. **证据链强制**：每个维度的 `rationale` 必须引用原文（填入 `evidence` 字段），**禁止编造讲稿/问答中不存在的内容**；若理由涉及原文之外的内容，该维度降档。
3. **讲错扣分**：若讲稿出现科学性错误（讲错），不单设维度——推理/步骤错 → 在「讲解逻辑」降档；术语/表述错 → 在「表达清晰度」降档。严重讲错（如"负负得负"）→「讲解逻辑」直接判 1 档。
4. **按轮次取材**：
   - 讲解逻辑：主要依据第 1 轮（讲题结构）
   - 错因诊断：预防面看第 1 轮，纠正面看第 2~N 轮
   - 表达清晰度、学情适配：综合全轮次
5. **总分换算**：`总分 = Σ(档位 × 权重) ÷ 5 × 100`，四舍五入取整。
6. **准入判定**：
   - 通过：总分 ≥ 70，且无任一维度 ≤ 2
   - 待定：总分 60~69，或存在单一维度 ≤ 2
   - 未过：总分 < 60（含严重讲错导致的总分过低）

## 5. 输出 JSON Schema

LLM 只输出一个 JSON 对象，无额外文字：

```json
{
  "dimensions": [
    {
      "name": "讲解逻辑",
      "level": 4,
      "rationale": "……（必填，说明为何给此档）",
      "evidence": "……（必填，引用原文）"
    },
    { "name": "表达清晰度", "level": 3, "rationale": "…", "evidence": "…" },
    { "name": "学情适配", "level": 3, "rationale": "…", "evidence": "…" },
    { "name": "错因诊断", "level": 4, "rationale": "…", "evidence": "…" }
  ],
  "total_score": 73,
  "verdict": "通过",
  "profile_tags": ["讲解逻辑清晰", "表达可提升"],
  "suggestions": ["……"]
}
```

字段约束：

| 字段 | 类型 | 约束 |
|---|---|---|
| `dimensions[].name` | string | 固定为 4 个维度名之一 |
| `dimensions[].level` | int | 1~5 整数 |
| `dimensions[].rationale` | string | 必填，说明给档理由 |
| `dimensions[].evidence` | string | 必填，引用原文（可截取） |
| `total_score` | int | 0~100，按公式换算 |
| `verdict` | string | 枚举："通过" / "待定" / "未过" |
| `profile_tags` | array | 2~4 个能力标签 |
| `suggestions` | array | 1~3 条可执行改进建议 |

> 程序化校验：解析 JSON 后，后端独立重算 `total_score` 与 `verdict`，与 LLM 输出比对；不一致时以**程序重算**为准（防止 LLM 算错分）。

## 6. Prompt 模板

### 6.1 System Prompt（静态，可缓存）

```
你是「约师」平台的资深初中数学教学能力评估专家，负责对大学生家教的情景模拟试讲进行评分。

你将收到一道题目的信息，以及试讲者的多轮文本（第 1 轮为讲稿，第 2~N 轮为答辩 / 回应学生疑问）。请严格按下方 Rubric 对 4 个维度分别评出 1~5 档，逐维度给出理由并引用原文，最后合成总分与准入判定。

## 评分方法（先核对，后分析，再打分）
1. **核对内容采分点**：按题目附带的「评分参考」第一节，逐条检查"该讲的知识点讲了没、讲对了没"；
2. **检查教学行为**：按「评分参考」第二节的观察点（结构、因果、简洁、重点、互动、搭桥、降维、预防），逐项检查——这是"啰嗦/无互动/无重点"等问题的落脚处，**不能只核对内容就打分**；
3. **找证据**：对每个维度，从原文中定位相关语句；
4. **对档位**：对照 Rubric 判断档位（就低不就高）；
5. **写理由**：给出 rationale 与 evidence。
严禁跳过核对与分析直接给分。
```

## 7. 完整示例（M-CZ-0031 错因诊断题 · 3 轮）

### 7.1 输入

**题目信息**
- 题号：M-CZ-0031 ｜ 题型：错因诊断题（答辩环节 · 第 2~N 轮）｜ 知识点：八年级 · 分式方程 ｜ 难度：中档
- 学生人设：初二，计算粗心，基础中等，做完题从不检验
- 教学目标：让学生理解增根产生的原因，并养成检验习惯
- 评分要点：指出 x=2 使分母为 0；解释增根如何产生；演示检验步骤；解释"分母不能为零"；给出防错建议

**第 1 轮（讲稿）**
"同学们好，今天我们学解分式方程。第一步，先找最简公分母，两边同乘。第二步，去分母变成整式方程。第三步，解出未知数。这里我要特别强调最后一步——一定要检验。因为两边同乘的那个分母可能等于 0，会出现增根。比如解出 x=2 这种，代回原方程分母就变成 0 了，所以解完必须代回最简公分母检验，是增根就要舍去。"

**第 2 轮**
- 学生疑问："老师，我解 1/(x-2)+3=(x-1)/(x-2)，去分母得 1+3(x-2)=x-1，解得 x=2，对吗？"
- 老师回应："我们来检验一下。把 x=2 代回原方程，分母 x-2 等于 0，而分母不能为 0，所以 x=2 不是原方程的解，这个就是增根。为什么会出现增根呢？因为你去分母时两边同乘了 x-2，当 x=2 时 x-2 就是 0，相当于两边同乘了 0，等式性质不允许这样。所以解分式方程必须检验，把增根舍去，这道题其实无解。"

**第 3 轮**
- 学生疑问："老师，那 0÷0 为什么也不行？"
- 老师回应："问得好。如果 1÷0 等于某个数 a，那 0×a 应该等于 1，但任何数乘 0 都是 0，找不到这样的 a。再看 0÷0，如果等于 b，那 0×b=0 对任何 b 都成立，结果不唯一。数学要求运算结果唯一确定，所以这两种情况都不允许，分母不能为 0。"

## 8. 与 NFR-Q 的对应关系

| NFR-Q | 本 prompt 如何保证 |
|---|---|
| Q1 一致性 ≥ 0.75 | rubric 全量嵌入 + 就低不就高，减少自由裁量空间 |
| Q2 可解释性 | 每个维度强制 `rationale` |
| Q3 可复现性 | 固定 rubric 版本 + 多轮采样中位数稳定（见 §9） |
| Q4 版本可追溯 | system prompt 与 rubric 版本号一并记录到评分结果 |
| Q6 理由无幻觉 | `evidence` 字段强制引用原文 + 人工抽检 |

## 9. 多轮采样与中位数（程序编排层，非提示词）

> 机制在**程序侧**实现：程序**独立调用 LLM 三次**，每次打分后取中位数。**绝不在提示词里让模型"评三次"**。

**关键：三次调用必须完全独立（无状态）**

- 每次调用都是**全新会话**，不共享上下文、不携带历史
- 否则模型会"记住"上一次的答案并照抄，出现**「错误地一致」**——三次给出一模一样的分数，中位数退化为单次，还造成"三次都同意"的假象（假的一致，实际是相关性污染）

- **采样次数**：N = 3（可配置）
- **温度**：temperature = 0.5（非 0；0 会使结果全同）
- **聚合**：每维度取 N 次档位的**中位数**作为最终档位；总分由中位数档位计算
- **变异系数（CV）**：每维度 N 次得分的 CV；> 20% 标记**低置信**，报告提示"建议重点人工复核"
- **成本**：LLM 调用 × N；N 次可**并行**，延迟不变，仅成本 × N
