# 评分 Prompt 草案（多轮结构化）

> 目的：把 [`README.md`](../README.md) 附录 A 的 Rubric 转成 LLM 可执行的评分指令，支持**异步多轮**（试讲 1 轮 + 答辩多轮）的转写输入。
> 配套：[functional_spec.md](requirements/functional_spec.md)（状态机 / 领域模型）· [nonfunctional_spec.md](requirements/nonfunctional_spec.md)（NFR-Q 质量指标）
> 状态：草案 v0.1，待用真实试讲样本做一致性验证后迭代。

---

## 1. 目的与定位

评分 prompt 是整条流水线的"标准答案"——它决定 AI 评分是否可信（NFR-Q1 一致性 ≥ 0.75 的源头）。设计要点：

1. **多轮结构化输入**：转写文本按轮次分段喂入，而不是把所有音频糊成一整段。
2. **rubric 全量嵌入**：5 维度 × 5 档行为描述直接写进 system prompt，作为唯一评分依据。
3. **强制证据链**：每个维度的理由必须引用转写原文，杜绝 LLM 幻觉（NFR-Q6）。
4. **输出可解析**：固定 JSON schema，便于程序化合成总分与判定。

---

## 2. 输入格式（多轮结构化）

每次评分，user prompt 组装如下（`{{ }}` 为占位符）：

```
【题目信息】
- 题号：{{题号}}
- 题型：{{题型}}（{{环节}}）
- 知识点：{{年级}} · {{知识点}}
- 难度：{{难度}}
- 学生人设：{{学生人设}}
- 教学目标：{{教学目标}}
- 评分要点：{{评分要点}}
- 常见偏差：{{常见偏差}}

【试讲环节 · 第 1 轮】（讲题转写）
{{讲题转写文本}}

【答辩环节 · 第 2 轮】
学生疑问：{{疑问1文本}}
老师回应：{{回应1转写文本}}

【答辩环节 · 第 3 轮】
学生疑问：{{疑问2文本}}
老师回应：{{回应2转写文本}}

（轮数由题目「疑问队列」长度决定，2~N 轮；无追问时此段省略）
```

> 评分要点 / 常见偏差来自题目本身（见 scenario-cards.md），它们与 rubric 一起构成评分锚点——这解决"AI 不知道这道题该讲什么"的问题。

## 3. 评分维度与 Rubric（嵌入版）

以下 5 张表原样嵌入 system prompt：

### 3.1 学科准确性（权重 25%）

| 档 | 行为描述 |
|---|---|
| 5 | 全程无科学性错误；概念表述严谨，主动点明易错边界（如"此处 x≠0"）；运算与推理无误 |
| 4 | 无科学性错误；概念表述基本准确，个别处不够严谨但不致误导 |
| 3 | 无实质性错误，但概念表述含糊、用词不规范（如把"方程的解"笼统说成"答案"），需学生自行补全 |
| 2 | 出现轻微错误或明显不严谨，可能造成轻微误导（如"约分就是去掉相同的数"） |
| 1 | 出现科学性错误（如"负负得负"、"不等式两边同乘负数不变号"），或无法完成讲解 |

### 3.2 讲解逻辑（权重 20%）

| 档 | 行为描述 |
|---|---|
| 5 | 结构完整（导入→讲解→例题→小结），因果链清晰，能说明"为什么这一步要这么做"，前后呼应 |
| 4 | 结构完整、条理清楚，个别环节衔接略生硬 |
| 3 | 能把内容讲完，但基本是"照着步骤念"，缺少"为什么"，结构松散 |
| 2 | 顺序混乱、跳跃，学生难以跟上 |
| 1 | 逻辑自相矛盾，或无法组织出完整讲解 |

### 3.3 表达清晰度（权重 15%）

| 档 | 行为描述 |
|---|---|
| 5 | 语言简洁准确，语速适中（约 200~260 字/分钟），术语规范且会做口语化转换，重点处有停顿强调，几乎无口头禅 |
| 4 | 表达清楚、语速基本合适，偶有口头禅但不影响理解 |
| 3 | 能听懂，但语速明显偏快或偏慢，或术语堆砌、或过度口语化，口头禅较多 |
| 2 | 表达含糊、重复啰嗦，需反复追问才能理解 |
| 1 | 语言混乱、声音过小或几乎无法理解 |

### 3.4 学情适配（权重 20%）

| 档 | 行为描述 |
|---|---|
| 5 | 准确判断并贴合学生水平，主动降维（换更简单的例子或类比），能用学生已有知识搭桥，预判学生难点 |
| 4 | 讲解难度基本匹配学生水平，有解释与铺垫意识 |
| 3 | 内容正确，但按自己的习惯难度讲，未考虑学生基础 |
| 2 | 明显超出或低于学生水平，使用了学生尚未学的工具 |
| 1 | 完全无视学生人设，自说自话 |

### 3.5 错因诊断（权重 20%）

| 档 | 行为描述 |
|---|---|
| 5 | 准确指出错误步骤与背后的概念误解，用学生能懂的方式重建正确认知，并给出防止再犯的方法 |
| 4 | 准确指出错误步骤并解释原因，但重建方式一般 |
| 3 | 能指出"这里错了"，但停留在运算层面，未触及概念原因 |
| 2 | 仅给出正确答案，未解释错因 |
| 1 | 未发现错误，或自身讲解出现科学性错误 |

> **两面说明**：本维度分「预防」「纠错」两面。上表 1~5 档描述**纠正面**（第 2~N 轮，学生出错后定位纠错）；**预防面**（第 1 轮讲题时主动预判并强调易错点）由学情适配维度与题目评分要点共同覆盖。

## 4. 评分规则与约束

1. **就低不就高**：行为介于两档之间时取较低档。
2. **证据链强制**：每个维度的 `rationale` 必须引用转写原文（填入 `evidence` 字段），**禁止编造转写中不存在的内容**；若理由涉及转写之外的内容，该维度降档。
3. **一票否决**：学科准确性评 1 档时，`veto.triggered = true`，`verdict` 必为"未过"，且理由须写明具体科学性错误。
4. **按轮次取材**：
   - 讲解逻辑：主要依据第 1 轮（讲题结构）
   - 错因诊断：预防面看第 1 轮，纠正面看第 2~N 轮
   - 学科准确性、表达清晰度、学情适配：综合全轮次
5. **总分换算**：`总分 = Σ(档位 × 权重) ÷ 5 × 100`，四舍五入取整。
6. **准入判定**：
   - 通过：总分 ≥ 70 且无维度 ≤ 2 且学科准确性 ≥ 3
   - 待定：总分 60~69，或存在单一维度 ≤ 2（非一票否决情形）
   - 未过：总分 < 60，或触发一票否决

## 5. 输出 JSON Schema

LLM 只输出一个 JSON 对象，无额外文字：

```json
{
  "veto": {
    "triggered": false,
    "reason": ""
  },
  "dimensions": [
    {
      "name": "学科准确性",
      "level": 4,
      "rationale": "……（必填，说明为何给此档）",
      "evidence": "……（必填，引用转写原文）"
    },
    { "name": "讲解逻辑", "level": 4, "rationale": "…", "evidence": "…" },
    { "name": "表达清晰度", "level": 3, "rationale": "…", "evidence": "…" },
    { "name": "学情适配", "level": 3, "rationale": "…", "evidence": "…" },
    { "name": "错因诊断", "level": 4, "rationale": "…", "evidence": "…" }
  ],
  "total_score": 73,
  "verdict": "通过",
  "profile_tags": ["概念阐释强", "表达可提升"],
  "suggestions": ["……"]
}
```

字段约束：

| 字段 | 类型 | 约束 |
|---|---|---|
| `veto.triggered` | bool | 仅学科准确性=1 时为 true |
| `dimensions[].name` | string | 固定为 5 个维度名之一 |
| `dimensions[].level` | int | 1~5 整数 |
| `dimensions[].rationale` | string | 必填，说明给档理由 |
| `dimensions[].evidence` | string | 必填，引用转写原文（可截取） |
| `total_score` | int | 0~100，按公式换算 |
| `verdict` | string | 枚举："通过" / "待定" / "未过" |
| `profile_tags` | array | 2~4 个能力标签 |
| `suggestions` | array | 1~3 条可执行改进建议 |

> 程序化校验：解析 JSON 后，后端独立重算 `total_score` 与 `verdict`，与 LLM 输出比对；不一致时以**程序重算**为准（防止 LLM 算错分）。

## 7. 完整示例（M-CZ-0031 错因诊断题 · 3 轮）

### 7.1 输入

**题目信息**
- 题号：M-CZ-0031 ｜ 题型：错因诊断题（答辩环节 · 第 2~N 轮）｜ 知识点：八年级 · 分式方程 ｜ 难度：中档
- 学生人设：初二，计算粗心，基础中等，做完题从不检验
- 教学目标：让学生理解增根产生的原因，并养成检验习惯
- 评分要点：指出 x=2 使分母为 0；解释增根如何产生；演示检验步骤；解释"分母不能为零"；给出防错建议

**第 1 轮（讲题转写）**
"同学们好，今天我们学解分式方程。第一步，先找最简公分母，两边同乘。第二步，去分母变成整式方程。第三步，解出未知数。这里我要特别强调最后一步——一定要检验。因为两边同乘的那个分母可能等于 0，会出现增根。比如解出 x=2 这种，代回原方程分母就变成 0 了，所以解完必须代回最简公分母检验，是增根就要舍去。"

**第 2 轮**
- 学生疑问："老师，我解 1/(x-2)+3=(x-1)/(x-2)，去分母得 1+3(x-2)=x-1，解得 x=2，对吗？"
- 老师回应："我们来检验一下。把 x=2 代回原方程，分母 x-2 等于 0，而分母不能为 0，所以 x=2 不是原方程的解，这个就是增根。为什么会出现增根呢？因为你去分母时两边同乘了 x-2，当 x=2 时 x-2 就是 0，相当于两边同乘了 0，等式性质不允许这样。所以解分式方程必须检验，把增根舍去，这道题其实无解。"

**第 3 轮**
- 学生疑问："老师，那 0÷0 为什么也不行？"
- 老师回应："问得好。如果 1÷0 等于某个数 a，那 0×a 应该等于 1，但任何数乘 0 都是 0，找不到这样的 a。再看 0÷0，如果等于 b，那 0×b=0 对任何 b 都成立，结果不唯一。数学要求运算结果唯一确定，所以这两种情况都不允许，分母不能为 0。"

### 7.2 期望输出

## 8. 与 NFR-Q 的对应关系

| NFR-Q | 本 prompt 如何保证 |
|---|---|
| Q1 一致性 ≥ 0.75 | rubric 全量嵌入 + 就低不就高，减少自由裁量空间 |
| Q2 可解释性 | 每个维度强制 `rationale` |
| Q3 可复现性 | 固定 rubric 版本 + 固定 temperature=0 |
| Q4 版本可追溯 | system prompt 与 rubric 版本号一并记录到评分结果 |
| Q5 一票否决可靠 | `veto` 字段 + 后端独立重算判定 |
| Q6 理由无幻觉 | `evidence` 字段强制引用原文 + 人工抽检 |
