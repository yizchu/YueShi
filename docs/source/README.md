# YueShi

> **约个好老师**
> 面向大学生家教的**教学能力评估方法**研究
> 第一版限定范围：**初中学段 × 数学学科**

## 0. 宏观速览

| 项 | 内容 |
|---|---|
| 评估对象 | 想成为初中数学家教的大学生 |
| 评估目标 | **准入**（卡住底线）+ **诊断**（产出画像） |
| 评估手段 | 初中数学学科知识测试 + 情景模拟试讲 |
| 输出 | 准入判定 + 能力总分 + 分维度画像 + 改进建议 |
| 用途 | 家教平台推荐系统的核心权重之一 |
| 第一版边界 | 只做初中数学，不做其他学段与学科 |

**为什么先聚焦一个学段 + 一个学科**：题库、评分标准（rubric）、评分提示词都必须逐学科打磨。聚焦能让标准做得更深、评分更准、成本更低；跑通一套可复制的评估方法后，再横向扩展到其他学科。

## 1. 模型定位

### 1.1 要解决什么

家长挑选大学生家教时，缺的是一句可靠的判断："这个人到底会不会**讲**初中数学？"

现有信息（在读学校、专业、高考分数）只能证明他"**会做题**"，不能证明他"**会讲课**"。本模型把这件事变成可测量、可比较、可复现的评估。

### 1.2 两项职责

- **准入（Gate）**：识别明显不合格者——学科知识有硬伤、讲解出现科学性错误、无法把话讲清楚。
- **诊断（Diagnose）**：对合格者给出能力画像，指出强项与短板，既支撑推荐排序，也用于指导老师改进。

### 1.3 产出物

1. **准入判定**：通过 / 待定 / 未过
2. **教学能力总分**（0~100）与分维度得分
3. **能力画像**：雷达图 + 标签 + 文字诊断
4. **可回放的试讲片段**（供家长查看）

## 2. 理论基础

采用教师知识领域的成熟框架，简化为工程可实现的两层：

| 层次 | 理论来源 | 在本模型中的对应 |
|---|---|---|
| **CK** 学科内容知识 | Ball 等 MKT 框架 | 模块 A：初中数学学科知识测试 |
| **PCK** 学科教学知识 | Shulman | 模块 B：情景模拟试讲 |

MKT 框架中更细的子类直接构成模块 B 的设计依据：

- **SCK**（专门内容知识，如"为什么负负得正"该如何解释）→ 情景类型① 概念阐释
- **KCS**（内容与学生知识，如预判学生会在哪里出错）→ 情景类型③ 错因诊断
- **KCT**（内容与教学知识，如如何组织讲解顺序）→ 情景类型② 例题讲解

> 完整 MKT 量表过于庞大（含 7 个子维度、上百道量表题），第一版只取对"大学生家教"最有区分度的子集。

## 3. 总体结构：两段式流水线

```
报名
  │
  ▼
┌──────────────────────────┐
│ 模块 A：学科知识测试（初筛）│──未过线──▶ 错题解析 + 7 天后可重考
└──────────────────────────┘
  │ 过线
  ▼
┌──────────────────────────┐
│ 模块 B：情景模拟试讲（诊断）│──▶ AI 评分 + 人工复核
└──────────────────────────┘
  │
  ▼
准入判定 + 能力画像 + 认证标识
```

**两段式的意义**：模块 A 是**低成本、可自动判分**的初筛；模块 B 是**高成本、需 AI 与人工**的诊断。先筛后评，既节省成本，也保证进入模块 B 的样本是有效的。

### 3.1 交互形式：异步双轮 + 文本疑问（第一版简化方案）

**简化动机**：完整版依赖实时语音、AI 虚拟学生与多模态评课，从 0 起步过重。第一版先把**实时性**和**语音交互**这两块最难的工程拿掉，只保留评估的核心价值。

**四项关键简化**

| 原设计 | 简化后 | 省掉的工程量 |
|---|---|---|
| AI 虚拟学生**实时语音**对话 | 学生的疑问以**文本**形式呈现 | 实时语音框架、TTS、打断处理、低延迟调优 |
| 实时音视频流 | **异步录播**提交 | WebRTC 实时通道、断线重连、并发控制 |
| 视频多模态分析 | **音频为主**（视频可选） | 多模态推理的 GPU 成本与工程复杂度 |
| 疑问由 LLM 动态生成 | 疑问由**情景卡预置** | LLM 生成的一致性风险与调试成本 |

> **关键判断**：现有 5 个评分维度（学科准确性 / 讲解逻辑 / 表达清晰度 / 学情适配 / 错因诊断）**都不依赖画面**，音频 + 转写文本即可完成评分。因此"音频版"不损失任何评分维度，多模态是增益项而非必需项。

**为什么疑问要"后置揭示"**

备课阶段**只给题目与学生人设，不给疑问**；老师讲完第一轮后才揭示疑问。这样既保留了"临场应变"的考察价值，又用纯文本异步的方式实现了它——全程不需要任何实时技术。

**两轮分工**

| 轮次 | 时长 | 主要考察维度 |
|---|---|---|
| 第一轮 · 讲题 | 8~10 分钟 | 学科准确性、讲解逻辑、表达清晰度、学情适配 |
| 第二轮 · 回应疑问 | 3~5 分钟 | 错因诊断、学情适配 |

## 4. 模块 A：初中数学学科知识测试（准入初筛）

### 4.1 内容范围与配比

依据《义务教育数学课程标准（2022 年版）》初中部分：

| 领域 | 占比 | 主要知识点 |
|---|---|---|
| 数与代数 | 45% | 有理数、整式与分式、方程与不等式、一次/反比例/二次函数 |
| 图形与几何 | 35% | 三角形、四边形、圆、相似、锐角三角函数、图形变换 |
| 统计与概率 | 15% | 数据的收集与描述、概率初步 |
| 综合与实践 | 5% | 跨知识点综合、建模应用 |

### 4.2 难度与题量

- 难度分布对齐中考：**基础 50% / 中档 35% / 拔高 15%**
- 题量 20~30 题，限时 30~45 分钟
- 客观题（选择 / 填空）自动判分，成本低

### 4.3 关键设计：不只考"会做"，还要考"会讲"

- 选题必须覆盖**初中典型易错点**：去分母漏乘、全等判定误用（SSA）、二次函数顶点式混淆、分式方程漏检验等
- 设置 **3~5 道「讲题题」**：只给题目，要求录制讲解视频
  - 讲题题**不判对错**，直接进入模块 B 的评估管道
  - 好处：知识测试与教学能力评估天然衔接，评估对象无需重复作答

### 4.4 判定规则

| 情况 | 处理 |
|---|---|
| 客观题正确率 ≥ 80% | 进入模块 B |
| 客观题正确率 < 80% | 判定未过，给出错题解析 + 7 天后可重考 |

## 5. 模块 B：教学能力评估（情景模拟）

### 5.1 情景类型（5 类）

| 类型 | 考察重点 | 初中数学示例 |
|---|---|---|
| ① 概念阐释 | 能否把抽象概念讲清楚（SCK） | "为什么负负得正？""函数到底是什么？" |
| ② 例题讲解 | 讲解逻辑与结构化（KCT） | 讲一道一元二次方程应用题 |
| ③ 错因诊断 | **诊断能力（本模型核心）**（KCS） | 学生解分式方程漏检验，判断错因并纠正 |
| ④ 分层适配 | 学情适配 | 同一知识点分别给基础生与尖子生讲 |
| ⑤ 答疑应变 | 回应疑问与临场应变 | 学生的**文本疑问**（异步呈现）："老师我有点听不懂了，这个 k 到底有啥用？" |

### 5.2 情景卡结构

每张情景卡是评估的最小单元：

| 字段 | 示例 |
|---|---|
| 情景编号 | M-CZ-0031 |
| 类型 | ③ 错因诊断 |
| 知识点 | 八年级 · 分式方程 |
| 学生人设 | 初二，计算粗心，基础中等 |
| 学生表现 | 解 `1/(x-2) + 3 = (x-1)/(x-2)` 时得 x=2，未检验 |
| 教学目标 | 让学生理解增根产生的原因，并养成检验习惯 |
| 评分要点 | 是否指出"去分母后可能产生增根"；是否演示检验步骤；是否解释"分母为什么不能为零" |

**设计原则**：窄而真实（还原一对一家教现场）；先精后多（每类情景先做 10~20 张）；防泄题（轮换 + 限次 + 录像比对）。

### 5.3 评分维度与权重

| 维度 | 权重 | 观察点 | 数据来源 |
|---|---|---|---|
| 学科准确性 | 25% | 概念、定理、运算是否准确，有无科学性错误 | 转写文本 |
| 讲解逻辑 | 20% | 导入→讲解→例题→小结的条理与因果 | 转写文本 |
| 表达清晰度 | 15% | 语速、术语使用、口语化程度、有无口头禅 | 音频 + 文本 |
| 学情适配 | 20% | 是否匹配学生水平、是否降维、是否回应困惑 | 文本（+ 视频） |
| 错因诊断 | 20% | 能否定位错因、给出针对性纠正 | 文本（+ 视频） |

> **一票否决**：学科准确性出现科学性错误 → 无论总分高低，直接判定未过。

### 5.4 评分标准（Rubric）

五个维度的完整 1~5 档行为描述、总分换算与准入判定规则，见 [附录 A](#附录-a完整评分-rubric5-维度--5-档)。

> **Rubric 的精细度是评分准确性的根本**，比任何模型选型都重要。评分必须逐条给出理由，不允许黑箱打分。

### 5.5 评估流程（异步双轮）

```
① 抽情景卡 —— 只展示题目与学生人设，不展示疑问
② 第一轮：老师讲题，录制 8~10 分钟
③ 提交 → ASR 转写
④ 揭示「学生的文本疑问」（1~2 条，来自情景卡预置）
⑤ 第二轮：老师针对疑问录制回应，3~5 分钟
⑥ 两轮转写合并 → LLM 按 rubric 评分 → 规则维度（语速 / 时长 / 口头禅）
→ 人工复核 → 合成报告
```

两轮的分工见 [3.1 交互形式](#31-交互形式异步双轮--文本疑问第一版简化方案)。

## 6. 评估智能体流水线

第一版智能体 = 一条**固定流水线**，不追求自主决策，先把稳定性和一致性做出来：

| 步骤 | 模块 | 职责 |
|---|---|---|
| 1 | 出题 | 按配比与难度从题库抽题、组装试卷与情景卡 |
| 2 | 采集 | 录播试讲、录音、限时控制 |
| 3 | 转写 | ASR 语音转文字（Whisper / 科大讯飞 / 阿里） |
| 4 | 评分 | LLM 按 rubric 分维度打分，并**逐条给出理由** |
| 5 | 诊断 | 汇总画像、生成能力标签与改进建议 |
| 6 | 复核 | 人工抽查 / 仲裁，纠偏并沉淀标注数据 |

### 6.1 Tier 1 —— 成熟技术，先跑通闭环

- **异步录播**：老师录音（或视频）讲题 + 回应文本疑问，无需实时通道
- **ASR 转写**：FunASR（Paraformer / SenseVoice）/ Whisper / 科大讯飞
- **LLM 文本评分**：按 rubric 对两轮转写文本打分
- **规则维度**：语速（字数÷时长）、时长控制、口头禅频率（"然后/那个"）
- **人工复核**：AI 初评 + Label Studio 人工抽查，保证信度
- **部署**：CPU 即可跑通（ASR 用轻量模型，LLM 先走 API），不需要 GPU

### 6.2 Tier 2 —— 智能化升级

- **疑问动态生成**：LLM 读第一轮转写，生成针对性疑问（替代情景卡预置），更贴近真实答疑
- **多模态评课**：接入 Qwen-VL / InternVL 类模型，分析表情、眼神、板书，并检测念稿
- **声纹 / 人脸反作弊**：确认本人试讲
- **（远期）实时语音 AI 虚拟学生**：若确有必要，再用 Pipecat / LiveKit Agents + 语音大模型补上实时交互

### 6.3 反作弊

- 人脸 / 声纹比对，确认与实名认证为同一人
- 念稿检测：视线轨迹、停顿模式、与题面文本重合度
- 题库轮换 + 限次

## 7. 诊断输出

不只给一个分数，而是"**判定 + 画像 + 建议**"三层输出：

- **准入判定**：通过 / 待定 / 未过
- **能力总分**：0~100（分维度加权）
- **能力画像**：雷达图 + 标签（如"概念阐释强 · 错因诊断弱"）
- **改进建议**：针对最低分维度给出具体可执行建议
- **展示物**：可回放的试讲片段（家长可看）

## 8. 信度与效度验证（研究设计）

模型能否被信任，取决于以下两项验证：

**信度**

- 评分者一致性：AI 评分与人工复核的一致性（ICC / Cohen's Kappa），目标 ≥ 0.75
- 内部一致性：各维度间 Cronbach's α
- 重测信度：同一人两次试讲的分数稳定性

**效度**

- 效标效度：能力总分与真实成单后家长评价、续费率的相关系数
- 区分效度：能否有效区分"会做题但不会讲"与"既会做也会讲"

**数据收集方式**：每场评估保留原始音视频 + 转写文本 + AI 分 + 人工分，形成标注数据集，用于持续校准 rubric 与评分提示词。

## 9. 与推荐系统的衔接

- 教学能力分作为推荐排序的**核心权重之一**
- 建议排序：同校 / 同高中 > 专业对口 > **教学能力分** > 家长评价 > 距离
- 能力分必须与真实成单评价**叠加**使用，**不唯分数论**，避免刷分与误判被放大

## 10. 数据与迭代

- **题库**：先做精，每类情景 10~20 张卡，逐步扩充
- **标注**：持续积累"AI 分 vs 人工分"的差异样本，反哺 rubric 修订
- **迭代**：从"分维度分数"逐步过渡到"能力标签 + 薄弱点推荐"

## 11. 落地路线

| 阶段 | 内容 |
|---|---|
| 第一阶段 | 完整 rubric（5 维度分档）+ 每类情景 10~20 张卡 + 模块 A 题库 100~200 题 |
| 第二阶段 | Tier 1 流水线跑通（异步录播 + ASR + LLM 评分 + 人工复核） |
| 第三阶段 | 信效度验证，校准 rubric 与评分提示词 |
| 第四阶段 | Tier 2 智能化升级：疑问动态生成 → 多模态评课 → 反作弊 |

> 技术选型与开源拼接清单见 [`docs/open-source-stack.md`](docs/open-source-stack.md)；情景卡起步题库见 [`docs/scenario-cards.md`](docs/scenario-cards.md)。

## 附录 A：完整评分 Rubric（5 维度 × 5 档）

**使用说明**

- 每维度按行为描述打分，**就低不就高**：行为介于两档之间时取较低档
- 总分换算：`总分 = Σ(维度档位分 × 权重) ÷ 5 × 100`
- 评分必须**逐条给出理由**，不允许黑箱打分

### A1. 学科准确性（权重 25%）

| 档 | 行为描述 |
|---|---|
| 5 | 全程无科学性错误；概念表述严谨，主动点明易错边界（如"此处 x≠0"）；运算与推理无误 |
| 4 | 无科学性错误；概念表述基本准确，个别处不够严谨但不致误导 |
| 3 | 无实质性错误，但概念表述含糊、用词不规范（如把"方程的解"笼统说成"答案"），需学生自行补全 |
| 2 | 出现轻微错误或明显不严谨，可能造成轻微误导（如"约分就是去掉相同的数"） |
| 1 | 出现科学性错误（如"负负得负"、"不等式两边同乘负数不变号"），或无法完成讲解 |

> **一票否决**：本维度为 1 档时，直接判定未过。

### A2. 讲解逻辑（权重 20%）

| 档 | 行为描述 |
|---|---|
| 5 | 结构完整（导入→讲解→例题→小结），因果链清晰，能说明"为什么这一步要这么做"，前后呼应 |
| 4 | 结构完整、条理清楚，个别环节衔接略生硬 |
| 3 | 能把内容讲完，但基本是"照着步骤念"，缺少"为什么"，结构松散 |
| 2 | 顺序混乱、跳跃，学生难以跟上 |
| 1 | 逻辑自相矛盾，或无法组织出完整讲解 |

### A3. 表达清晰度（权重 15%）

| 档 | 行为描述 |
|---|---|
| 5 | 语言简洁准确，语速适中（约 200~260 字/分钟），术语规范且会做口语化转换，重点处有停顿强调，几乎无口头禅 |
| 4 | 表达清楚、语速基本合适，偶有口头禅但不影响理解 |
| 3 | 能听懂，但语速明显偏快或偏慢，或术语堆砌、或过度口语化，口头禅较多 |
| 2 | 表达含糊、重复啰嗦，需反复追问才能理解 |
| 1 | 语言混乱、声音过小或几乎无法理解 |

### A4. 学情适配（权重 20%）

| 档 | 行为描述 |
|---|---|
| 5 | 准确判断并贴合学生水平，主动降维（换更简单的例子或类比），能用学生已有知识搭桥，预判学生难点 |
| 4 | 讲解难度基本匹配学生水平，有解释与铺垫意识 |
| 3 | 内容正确，但按自己的习惯难度讲，未考虑学生基础 |
| 2 | 明显超出或低于学生水平，使用了学生尚未学的工具 |
| 1 | 完全无视学生人设，自说自话 |

### A5. 错因诊断（权重 20%）

| 档 | 行为描述 |
|---|---|
| 5 | 准确指出错误步骤与背后的概念误解，用学生能懂的方式重建正确认知，并给出防止再犯的方法 |
| 4 | 准确指出错误步骤并解释原因，但重建方式一般 |
| 3 | 能指出"这里错了"，但停留在运算层面，未触及概念原因 |
| 2 | 仅给出正确答案，未解释错因 |
| 1 | 未发现错误，或自身讲解出现科学性错误 |

### A6. 总分换算示例

各维度得分：学科准确性 4、讲解逻辑 4、表达清晰度 3、学情适配 3、错因诊断 4

```
总分 = (4×0.25 + 4×0.20 + 3×0.15 + 3×0.20 + 4×0.20) ÷ 5 × 100
     = (1.00 + 0.80 + 0.45 + 0.60 + 0.80) ÷ 5 × 100
     = 3.65 ÷ 5 × 100
     = 73
```

### A7. 准入判定

| 判定 | 条件 |
|---|---|
| **通过** | 总分 ≥ 70，且无任一维度 ≤ 2，且学科准确性 ≥ 3 |
| **待定** | 总分 60~69，或存在单一维度 ≤ 2（非一票否决情形） |
| **未过** | 总分 < 60，或触发一票否决 |

### B2. 设计规范

1. **窄而真实**：还原一对一家教现场，学生人设要具体到"会在哪一步卡住"
2. **一卡一考点**：一张卡只考察一个明确的教学难点，不塞多个知识点
3. **内容可核验**：数学内容必须经得起推敲，评分要点需经同行评审
4. **必写常见偏差**：不写出典型错误讲法，低分档就无法校准
5. **人设分级**：同一知识点配基础 / 中等 / 拔高三种人设，支撑分层适配评估
6. **先精后多**：每类先做 10~20 张，覆盖课标主干，宁缺毋滥

### B3. 完整示例（③ 错因诊断）

| 字段 | 内容 |
|---|---|
| 情景编号 | M-CZ-0031 |
| 类型 | ③ 错因诊断 |
| 年级 | 八年级 |
| 知识点 | 分式方程的解法 |
| 难度 | 中档 |
| 学生人设 | 初二，计算粗心，基础中等，做完题从不检验 |
| 学生表现 | 解 `1/(x-2) + 3 = (x-1)/(x-2)` 时，去分母得 `1 + 3(x-2) = x - 1`，解得 `x = 2`，写完就交 |
| 教学目标 | 让学生理解增根产生的原因，并养成检验习惯 |
| 评分要点 | ① 指出 `x = 2` 使分母为 0，原方程无意义；② 解释增根如何产生（去分母时乘了可能为 0 的式子）；③ 演示检验步骤；④ 解释"为什么分母不能为零"；⑤ 给出防错建议（解完必须代回最简公分母检验） |
| 常见偏差 | 只说"答案错了，应该是无解"却不解释原因；或试讲者自己也没意识到要检验 |
| 建议时长 | 10 分钟 |
