## 1. Measuring Teaching with LLMs（⭐ 最相关）

**核心内容**：作者发现**通用 GPT 式 LLM 难以可靠地应用复杂的课堂观察量表（rubric）**，于是用**句子级 embedding + 多任务 encoder**（非 subword tokenization，非 prompting）训练专用模型，同时给 25 个教学维度（MQI + CLASS 量表）打分。数据是 NCTE 主研究（1762 节课、317 名教师、4-5 年级数学、77 万条专家评分）。结果：3/5 的 embedding 模型达到**人类水平甚至超人**（CLASS 相关 >0.65，MQI 超过人类平均）；成熟模型更多把分数差异归因于**整节课**而非孤立话语；聚合分数与学生增值（VAM）对齐，但**单项层面不对齐**。

**对本项目的启发**（最重要）：

1. **⚠️ 通用 LLM prompting 可能不够**：论文明确说 GPT 式模型对教学量表"表现有限"，需要**专用 encoder + 微调**。这是对约师"LLM-as-judge 提示词打分"路线的**直接警示**——约师可能最终需要"微调专用评估器"，而非只靠 prompt。
2. **外部效度视角**：论文用学生增值（VAM）做外部效度，而非只对齐人类评分员。约师对应的"外部效度"是**家教成单率/续费率/家长评价**——应作为最终检验，而非只追求 AI-人工一致性。
3. **整课 vs 单句**：成熟模型靠"整节课的宏观模式"，而非孤立话语 → 印证约师"多轮 + 全转写 + 按维度找证据"的设计方向。
4. **人类评分员信度本来就低**：专家自己信度都不高 → 约师 NFR-Q1（≥0.75）需谨慎。

**局限性**：数据窄（仅美国 4-5 年级数学）；专用模型不可泛化；未达高风险部署标准；作者明言"**不应解读为支持用 GPT 式通用 LLM 做类似评估**"。

## 2. OASIS（生产级同类）

见独立精读 [shakur-2026-oasis.md](shakur-2026-oasis.md)。要点：医学教育的 rubric 多模态评分平台，产出 per-criterion scores + evidence + rationales，生产 7000+ 次。

**启发**：输出结构（维度分 + 证据 + 理由）、转写优先、人工复核状态——与约师几乎同构。
**局限性**：只发报告不发代码；医学场景，未验证跨领域。

## 3. G-Eval（Liu et al. 2023, NeurIPS）

**核心内容**：LLM-as-judge 方法。用 GPT-4 **自动生成评估标准/步骤（rubric）**，再用**思维链（CoT）** + 表单式打分，比传统参考类指标更接近人类。

**启发**：① "rubric + CoT" 提升 LLM 评委质量——约师评分 prompt 可引入"先写出评分依据，再给分"的 CoT 步骤；② rubric 的生成可自动化。
**局限性**：依赖 GPT-4（成本）；自动生成的 rubric 可能不可靠；仍有 LLM 评委的 bias（长度/位置等）。

---

## 4. Prometheus（Kim et al. 2023）

**核心内容**：把开源 Llama-2 **微调**成可自托管的评估器，用"rubric + 参考答案 + 候选 + 反馈"的大规模数据训练；能用**自定义 rubric** 给 1~5 的细粒度反馈，相关度接近 GPT-4 和人类。

**启发**：① **可自托管的 rubric 评估器**——约师若不想依赖闭源 API，可微调自己的"初中数学教学评估器"；② 用"rubric 化反馈"训练数据，与约师的 rubric 思路一致。
**局限性**：需要大量训练数据；开源模型能力弱于 GPT-4；仍有 bias。

---

## 5. JudgeLM（Zhu et al. 2023）

**核心内容**：微调 LLM 作为可扩展评委；用**位置交换 + 聚合**缓解位置 bias；构建大规模评判数据集。

**启发**：**位置 bias 缓解方法**（交换顺序、双向打分取平均）——约师多轮答辩评分可借鉴。
**局限性**：微调成本；评委 bias 无法根除；偏"通用输出评判"，与教学领域有距离。

---

## 6. Automated Essay Scoring with GPT-4（作文评分）

**核心内容**：用 GPT-4 按 rubric 给本地分班考试作文打分，研究**提示策略、评分者内信度（intra-rater reliability）、与人类分数的对齐**。

**启发**：① 教育领域的 rubric 评分 + **评分者内信度（ICC 类度量）**——正是约师 NFR-Q1 的度量；② "提示策略影响信度"与约师评分 prompt 工程直接相关。
**局限性**：单一场景（分班作文）；依赖 prompting，受 GPT-4 局限；未见跨场景泛化验证。

---

## 7. EvaluAI（开源框架）

**核心内容**：开源的 LLM 框架，用于**学生作品自动评估 + 反馈生成**（摘要未能抓取全文，细节待补）。

**启发**：又一个与 OASIS 类似的"开源评估框架"，可作为工程实现的第二参考。
**局限性**：⚠️ 细节未核实（ScienceDirect 付费墙）。

## 8. 横向小结（对本项目）

| 主题 | 一致结论 |
|---|---|
| 路线 | rubric + LLM 评分是主流、可行（G-Eval/Prometheus/AES/OASIS 同证） |
| 信度度量 | 用 ICC/评分者信度，别用 accuracy（AES、Measuring Teaching 同证） |
| **最大警示** | **通用 GPT 式 prompting 可能不够**（Measuring Teaching 发现需专用微调模型） |
| 外部效度 | 最终要验证"对学生学习/成单的影响"，而非只对齐人类评分员 |
